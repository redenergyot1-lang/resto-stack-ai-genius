# RestoStack — Frontend

A full-screen, web-first food delivery storefront UI, built with React, Tailwind CSS, and React Router. This is the **frontend** half of RestoStack — built against realistic mock data so it's ready to swap onto a real Express + MySQL + Razorpay backend (see `server/` for the matching Express API).

## Run it (on Replit or locally)

```bash
npm install
npm run dev
```

Then open the forwarded port (5173). To also run the backend locally, see `server/README.md` (it works out of the box on mock data — no database required).

## What's included

- **Landing page** — hero with live delivery-city display, search, culinary categories, top rated, offers
- **Delivery location** — searchable selector covering 150+ Indian cities and towns (`src/data/cities.js`), persisted for the session, with restaurant listings/search/hero copy all updating to match. Cities outside the mock catalog's 10 covered cities show a friendly "not available yet" fallback instead of an empty page.
- **Restaurant listing** — dedicated **Filters** button opening a slide-in drawer (Rating, Delivery Time, Cost for Two, Cuisine, Veg Only, Non-Veg, Offers, Open Now, Fast Delivery, Most Ordered, Newly Added, Top Rated) with staged Apply / Reset / Clear All, plus a separate sort dropdown (rating, delivery time, cost)
- **Restaurant detail** — banner, info, popular dishes, menu with its own sort/filter row, per-dish reviews (write + edit, persisted to localStorage)
- **Search** — instant dropdown suggestions across restaurant names, cuisines, and dish names, scoped to the selected delivery city, with highlighting and empty states
- **Cart** — quantity controls, bill summary (subtotal, delivery fee, platform fee, tax), mock checkout flow
- **Auth** — Login / Signup with mock email auth + mock Google sign-in, shaped exactly like a real JWT flow so it's a drop-in swap
- **Dashboard** — profile, order history, saved addresses, wishlist, my reviews, support tickets, account settings
- **Info pages** — About, Careers, Partner with us, Refunds & Cancellations, Contact us (`src/pages/InfoPage.jsx`) — every footer link goes somewhere real

## Mock data

`src/data/restaurants.js` is generated by `scripts/generate-data.cjs` — 54 restaurants across 12 cuisines and 10 cities, each with 10–12 menu items. Regenerate anytime:

```bash
npm run generate:data
```

Images currently use [placehold.co](https://placehold.co) colour-coded placeholders — swap these for real photography before client delivery (see `image` / `banner` fields in the generator).

## Wiring up the real backend later

`src/services/api.js` is a ready-to-use Axios client matching every route in `server/` (auth, restaurants, menu, search, reviews, cart) — point `VITE_API_URL` (see `.env.example`) at a running instance of the server and start swapping calls in one context at a time. Everything that should eventually hit the Express API is also marked with a `// TODO:` comment, mainly in:

- `src/context/AuthContext.jsx` — login / signup / Google OAuth
- `src/context/CartContext.jsx` — cart shape is already API-ready
- `src/pages/Cart.jsx` — checkout → Razorpay order creation + verification
- `src/context/LocationContext.jsx` — session-only city selection today; swap for a `GET/PUT /api/users/me/location`-style call once accounts carry a saved location
- `src/data/restaurants.js` — swap for `GET /api/restaurants`, `GET /api/restaurants/:id`
